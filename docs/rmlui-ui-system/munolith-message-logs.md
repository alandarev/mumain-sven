# Chat and notices in Munolith

Chat history uses native message identities, filters, frame/transparency choices and scroll/resize controls, with complete flowing rows sized from the native text fact. The scrollbar and resize handle are interactive; message text passes world clicks through. Wheel over framed history scrolls earlier or later messages. F2 toggles the whisper filter, F3 toggles whisper entry, F4 cycles framed history size, F5 toggles the frame, and PageUp/PageDown page framed history, including while a chat field is focused. These controls retain the unsent draft. Sender hover/right-click keeps the native unsent whisper target.

The six system-notice entries use the same readable row treatment and distinct error color in the passive workspace column below the corner status strip. Legacy and Modern retain their original documents and appearance.

Munolith also supplies a passive character-selection server-message card. It keeps
all five native rows, wraps their full text and uses a physical text minimum.
Resizing the character-selection scene recreates its native windows and clears
messages; a populated resize check must deliver the messages after resizing.

Scrolling help and server announcements share a 28-pixel rail above the workspace
header. Native horizontal movement, server colors, fade and help/notice precedence
remain unchanged. The rail's text is bounded to readable physical sizes. The header
reserves its height so the ticker cannot cover location or toolbar controls.
At narrow widths the six-row system-notice column stays in the left world lane,
away from the right-side Temple and siege controls.

The Munolith toolbar omits the unused cash-shop action.

The ticker bridge follows the native renderer's independent notice branch: a
priority notice starts when the help lane reaches zero alpha, including the
frame that completes its fade.

Temple's temporary score/tutorial content uses a separate passive foreground
view above system notices. Its tactical map and controls retain their background
view. The transient view receives the same native fields and flags, keeps native
lifetimes and hides on map exit. Other themes keep their existing combined view.
